AI Document Intelligence Assistant

Goal: Users upload documents, the system processes/indexes them, and users ask natural-language questions and receive grounded answers with source/page citations.

Keep these features

Document support
PDF
DOCX
TXT
CSV
PPTX
Markdown
Scanned PDF/Image OCR

AI/RAG
Chat with one or multiple documents
Semantic/vector search
Keyword search
Hybrid search
Reranking
Metadata filtering
Conversation-aware follow-up questions
Source/page citations
Confidence/relevance score
Streaming answers

Small value-add features
Document summary
Key points
Compare two documents
Generate quiz/questions

Basic app features
Upload/delete documents
Chat history
Rename/delete chats
Dark mode
Simple analytics: files, chats, queries, response latency

POC Tech Stack

Use one good option per layer:
Layer	Choice
Frontend	Next.js + React + TypeScript
Styling	Tailwind CSS + shadcn/ui
Backend	Python + FastAPI
AI orchestration	LangChain
LLM	Gemini or OpenAI
Embeddings	HuggingFace/Sentence Transformers
Vector DB	ChromaDB
Database	PostgreSQL
OCR	Tesseract/PaddleOCR
PDF parsing	PyMuPDF
DOCX	python-docx
PPTX	python-pptx
Search	Vector Search + BM25
Reranking	Cross-Encoder
Streaming	SSE
Deployment	Docker

You can even start with SQLite instead of PostgreSQL and migrate later.

Phase 4 — Upload API

Implement:

POST /api/documents/upload
GET /api/documents
GET /api/documents/{id}
DELETE /api/documents/{id}

Validate file type and size and generate a unique document ID.

Phase 5 — Parsers

Create a common interface:

DocumentParser
      |
 +----+----+-----+-----+-----+
 |    |    |     |     |     |
PDF DOCX TXT   CSV   PPTX   MD

Each parser returns standardized text plus metadata.

Phase 6 — OCR

For scanned PDFs/images:

Image/Scanned PDF
       ↓
OCR
       ↓
Extract Text
       ↓
Normalize

Only invoke OCR when necessary.

Phase 7 — Cleaning

Remove or normalize:

excessive whitespace
repeated headers/footers
broken lines
empty content
unnecessary control characters

Preserve page numbers and headings for citations.

Phase 8 — Chunking

Transform:

Document
 ↓
Pages/Sections
 ↓
Chunks

Start around:

Chunk size: 800–1200 tokens
Overlap: 100–200 tokens

Tune later based on retrieval quality.

Each chunk should carry metadata such as:

document_id
filename
page_number
section
chunk_id
Phase 9 — Embeddings

Generate embeddings for each chunk.

Chunk
 ↓
Embedding Model
 ↓
Vector
Phase 10 — ChromaDB

Store:

Vector
Text
Metadata

Test semantic search before adding an LLM.

For example:

Question:
"What was revenue in 2025?"

Verify the most relevant chunks are actually retrieved.

Phase 11 — Basic RAG

Now implement:

Question
 ↓
Embedding
 ↓
Vector Search
 ↓
Top-K chunks
 ↓
Prompt
 ↓
LLM
 ↓
Answer

At this point, you have a working MVP.

Phase 12 — Hybrid search

Upgrade retrieval:

Question
   |
   +--------------+
   |              |
   v              v
Vector Search   BM25
   |              |
   +------+-------+
          |
          v
     Merge Results

This improves handling of exact names, codes, IDs, dates, and technical terminology.

Phase 13 — Reranking

Don't send every retrieved result directly to the LLM.

Use:

Retrieve 15–20
      ↓
Reranker
      ↓
Best 4–6
      ↓
LLM
Phase 14 — Metadata filtering

Allow queries restricted to:

Specific Document
Specific File Type
Specific Page
Specific Date

This is particularly useful for multi-document chat.

Phase 15 — Citations

Answers should show evidence such as:

Revenue increased 12% year-over-year.

Sources:
Annual Report.pdf — Page 17
Annual Report.pdf — Page 22

Clicking a citation should open the relevant document/page where feasible.

Phase 16 — Confidence

Return a retrieval-grounded relevance indicator rather than pretending it is a calibrated probability:

Answer

Sources

Retrieval relevance:
High

Derive it from retrieval/reranking signals.

Phase 17 — Streaming

Instead of waiting for the complete response:

Generating answer...

stream tokens progressively into the UI using SSE.

Phase 18 — Chat history

Create database tables for:

users
documents
chats
messages

Support:

create chat
rename chat
delete chat
retrieve chat history
Phase 19 — Summary

Add:

POST /api/ai/summarize

Support concise and detailed summaries.

Phase 20 — Key points

Add:

POST /api/ai/key-points
Phase 21 — Quiz

Add:

POST /api/ai/quiz

For example, generate 5/10/20 MCQs grounded in the selected document.

Phase 22 — Document comparison

Allow:

Document A
+
Document B
 ↓
Compare

Produce differences, similarities, missing information, and key changes with citations.

Phase 23 — Search interface

Add a dedicated document search:

Search documents...

Back it with hybrid retrieval.
